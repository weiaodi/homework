# 汽车销售管理平台介绍

## 项目背景

汽车销售管理系统是 2023 - 2024 第一学期的综合性期末项目，跨足以下核心课程：

1. Web 技术与应用

2. 软件工程

3. 数据库原理

我们致力于提供一套完整的汽车销售解决方案，并结合现代技术进行最佳实践。

## 技术栈

- 后端：使用 Nest.Js，基于 Node.Js 和 TypeScript 构建，使用 JWT 鉴权

- 前端：使用 Vue、Element UI、Echarts 和 TailwindCSS 设计用户界面

- 数据库：使用 MySQL，通过 Prisma ORM 和 SQL 进行操作

- 云计算：华为云耀云服务器 HECS、七牛云对象存储 Kodo、七牛云内容分发网络 CDN

- 部署：Ubuntu、使用 Nginx 进行反向代理

## 3.2 需求分析

### 3.2.1 功能性需求

#### 1. 用户认证与权限管理功能

(1) 用户注册与登录：系统应支持员工注册和登录功能，使用手机号作为唯一标识，密码采用加密存储。
(2) 角色权限控制：系统应实现基于角色的访问控制（RBAC），支持 USER、ADMIN、ROOT 三种角色，不同角色拥有不同的操作权限。
(3) 会话管理：系统应使用 JWT 令牌进行身份认证，支持自动登录和会话保持功能，令牌有效期设置为 30 天。

#### 2. 产品管理功能

(1) 产品信息管理：系统应支持汽车产品的增删改查操作，包括产品名称、型号、价格、简介、海报等信息的维护。
(2) 产品库存查询：系统应能查询指定产品在不同仓库的库存分布情况，提供实时的库存数据。
(3) 产品销售统计：系统应能统计每个产品的销售数量和销售趋势，支持按年度进行销售数据分析，生成产品销售报表。

#### 3. 仓库管理功能

(1) 仓库信息管理：系统应支持仓库的创建、修改、删除和查询，包括仓库位置等基本信息。
(2) 库存追踪：系统应能追踪每个仓库中不同产品的库存数量，支持库存的实时查询和更新。
(3) 库存关联查询：系统应能查询指定仓库中所有有库存的产品信息，提供仓库库存的完整视图。

#### 4. 供应商管理功能

(1) 供应商信息管理：系统应支持供应商基本信息的维护，包括供应商名称、联系方式、公司信息等。
(2) 供应商关联查询：系统应能查询供应商的供应记录，分析供应商的供应表现，追踪供应商的供应历史。
(3) 供应商统计报表：系统应提供供应商相关的统计报表，方便分析供应链表现，评估供应商绩效。

#### 5. 订单管理功能

(1) 订单创建与编辑：系统应支持订单的创建、修改和删除操作，订单需关联产品、员工和仓库信息，记录订单创建时间。
(2) 订单查询：系统应支持订单的分页查询和详情查询，提供订单的完整信息展示，包括产品信息、员工信息、仓库信息等。
(3) 订单库存联动：系统应确保订单创建时自动减少库存，订单删除时自动恢复库存，保证数据一致性，防止库存数据错误。

#### 6. 供应记录管理功能

(1) 供应记录创建：系统应支持供应记录的创建，记录供应商、产品、仓库、数量、时间等供应信息。
(2) 供应记录查询：系统应支持供应记录的分页查询和详情查询，提供完整的供应信息展示。
(3) 供应记录维护：系统应支持供应记录的修改和删除操作，确保供应数据的准确性和完整性。

#### 7. 数据统计与可视化功能

(1) 销售数据统计：系统应能统计总营业额、总成交量、仓库数量、员工数量等关键业务指标，提供实时的业务数据概览。
(2) 数据可视化展示：系统应使用 ECharts 提供销售数据的可视化图表，包括销售趋势、产品排名、员工销售排行榜等，支持柱状图、折线图等多种图表类型。
(3) 数据分析报表：系统应能生成各类业务分析报表，支持销售数据的多维度分析，包括年度销售趋势、产品热销榜、员工销售榜等。

#### 8. 文件管理功能

(1) 图片上传：系统应支持产品海报等图片文件的上传功能，集成七牛云对象存储服务，支持图片的快速上传和存储。
(2) 文件存储管理：系统应能管理上传的文件，支持文件的存储、访问和删除操作，通过 CDN 加速文件访问速度。

#### 9. 用户界面功能

(1) 交互界面：系统应提供友好的 Web 用户界面，支持各功能模块的便捷操作，界面设计简洁直观。
(2) 数据展示：系统应以清晰的方式展示查询结果、统计数据和可视化图表，提供良好的数据可视化体验。
(3) 响应式设计：系统界面应适配不同屏幕尺寸，提供良好的用户体验，支持桌面端和移动端访问。

### 3.2.2 非功能性需求

#### 1. 性能需求

(1) 响应时间：系统应保证 API 接口响应时间在合理范围内，常规查询操作应在 1 秒内完成响应，确保用户操作的流畅性。
(2) 准确性：数据统计和查询结果的准确率应达到高水平，确保业务数据的准确性和可靠性，避免数据错误导致的业务问题。
(3) 资源利用率：系统应高效利用计算资源，如 CPU、内存和存储，优化数据库查询性能，降低系统运行成本，提高资源利用效率。

#### 2. 可靠性需求

(1) 稳定性：系统应具有高稳定性，确保长时间运行而无需频繁重启或维护，支持 7×24 小时运行，保证业务连续性。
(2) 数据备份：定期备份系统中的各项重要数据，包括订单数据、产品信息、库存数据等，以防数据丢失，确保数据安全。
(3) 可测试性：系统应易于进行性能测试，测试其稳定性、响应时间、最大工作能力、资源使用情况等，支持自动化测试流程。

#### 3. 安全性需求

(1) 身份认证：系统应使用 JWT 令牌进行身份认证，确保用户身份的安全性，防止未授权访问。
(2) 密码加密：系统应对用户密码进行加密存储，使用 SHA-256 哈希算法保护密码安全，防止密码泄露。
(3) 权限控制：系统应实现严格的权限控制，防止未授权用户访问敏感功能，确保不同角色只能访问其权限范围内的功能。
(4) 数据验证：系统应对用户输入进行验证，防止 SQL 注入、XSS 等安全攻击，确保系统安全。

#### 4. 可用性需求

(1) 易用性：系统应易于使用，界面简洁直观，操作流程清晰，无需复杂培训即可上手，降低用户学习成本。
(2) 可访问性：系统应支持跨域访问，提供 RESTful API 接口，便于前端调用和系统集成，支持多种客户端访问。
(3) 兼容性：系统应兼容主流浏览器，确保在不同浏览器环境下正常运行，提供一致的用户体验。

#### 5. 可维护性需求

(1) 代码规范：系统应采用 TypeScript 编写，遵循统一的代码规范和最佳实践，提高代码可读性和可维护性。
(2) 模块化设计：系统应采用模块化架构，各功能模块独立，便于维护和功能扩展，支持功能的独立开发和部署。
(3) 日志记录：系统应记录关键操作日志，便于问题排查和系统监控，支持系统运行状态的实时监控。

#### 6. 法律和合规需求

(1) 合规性：系统开发和运营必须符合所有相关法律法规，包括数据保护法、隐私保护等相关规定。
(2) 数据安全标准：系统应遵循数据安全标准，保护用户隐私和业务数据安全，确保数据的合法使用和存储。

## 项目创新点

### 1. 统一的错误处理与响应机制

**创新描述**：系统实现了三层统一的错误处理和响应机制，确保 API 响应格式的一致性。

- **CommonService 统一服务层**：提供 `handlePrismaExecution` 方法统一处理 Prisma 操作异常，避免重复的错误处理代码
- **ResponseInterceptor 响应拦截器**：全局统一格式化所有 API 响应，确保响应数据结构的一致性
- **HttpStatusFilter 异常过滤器**：统一捕获和处理 HTTP 异常，提供友好的错误提示信息

**技术价值**：提高了代码的可维护性，减少了重复代码，统一了错误处理逻辑。

### 2. 混合数据访问模式（Prisma ORM + 原生 SQL）

**创新描述**：系统采用混合数据访问策略，在简单 CRUD 操作中使用 Prisma ORM，在复杂统计查询中使用原生 SQL。

- **简单操作使用 Prisma**：利用 Prisma 的类型安全和自动补全特性，提高开发效率
- **复杂查询使用原生 SQL**：在数据统计、排名查询等复杂场景下使用原生 SQL，充分发挥数据库性能优势
- **类型安全的通用查询方法**：`CommonService.getEntityById` 使用 TypeScript 泛型，提供类型安全的实体查询

**技术价值**：兼顾开发效率和查询性能，在保证类型安全的同时实现高性能的数据统计功能。

### 3. 复杂多维度数据统计查询

**创新描述**：系统实现了复杂的多维度数据统计功能，包括员工销售排行榜和汽车热销排行榜。

- **员工销售榜**：统计近 5 年销售额最高的前 7 名员工，提供年度销售额趋势数据，支持折线图可视化
- **汽车热销榜**：统计近 10 年销量最高的前 7 款汽车，使用 CROSS JOIN 和 LEFT JOIN 组合查询，确保即使某年无销量也能显示完整时间序列
- **动态时间序列生成**：自动生成连续的时间序列数据，填补缺失年份的数据，保证图表展示的完整性

**技术价值**：通过复杂的 SQL 查询实现了多维度、多时间段的业务数据分析，为管理决策提供数据支持。

### 4. 订单库存自动联动机制

**创新描述**：系统实现了订单与库存的自动联动，确保库存数据的实时准确性。

- **订单创建自动减库存**：创建订单时自动减少相应仓库中对应产品的库存数量
- **订单删除自动恢复库存**：删除订单时自动将库存数量加 1，恢复库存状态
- **数据一致性保证**：通过业务逻辑层面的联动，确保库存数据与订单数据的一致性

**技术价值**：避免了库存数据与订单数据不一致的问题，提高了数据的准确性和可靠性。

### 5. 事务处理保证数据一致性

**创新描述**：系统在关键删除操作中使用数据库事务，确保级联删除的数据一致性。

- **产品删除事务**：删除产品时，在事务中依次删除关联的订单、供应记录、库存记录，最后删除产品本身
- **仓库删除事务**：删除仓库时，在事务中依次删除关联的供应记录、订单、库存记录，最后删除仓库本身
- **用户删除事务**：删除用户时，在事务中删除用户及其关联的订单记录

**技术价值**：通过事务机制保证了级联删除的原子性，避免了数据不一致的问题。

### 6. 云存储与 CDN 集成

**创新描述**：系统集成了七牛云对象存储和 CDN 服务，实现了高效的文件管理。

- **七牛云对象存储**：产品海报等图片文件上传到七牛云 Kodo 存储服务
- **CDN 加速**：通过七牛云 CDN 加速文件访问，提高图片加载速度
- **动态上传令牌**：提供安全的动态上传令牌生成机制，保障文件上传的安全性

**技术价值**：减轻了服务器存储压力，提高了文件访问速度，提升了用户体验。

### 7. 类型安全的通用服务设计

**创新描述**：系统通过 TypeScript 泛型实现了类型安全的通用服务方法。

- **通用实体查询**：`getEntityById<T>` 方法使用泛型，支持查询任意类型的实体，同时保证类型安全
- **统一异常处理**：`handlePrismaExecution<T>` 方法使用泛型，支持不同类型的返回值，同时统一处理异常

**技术价值**：在提高代码复用性的同时，保持了 TypeScript 的类型安全特性，减少了运行时错误。

### 8. 分页查询与数据聚合优化

**创新描述**：系统在分页查询中实现了高效的数据聚合，避免 N+1 查询问题。

- **并发数据聚合**：使用 `Promise.all` 并发查询关联数据，提高查询效率
- **分页信息完整**：提供当前页码、每页数量、总页数、总记录数等完整的分页信息
- **数据关联查询**：在分页查询中自动聚合关联实体的详细信息，减少前端请求次数

**技术价值**：优化了查询性能，提高了用户体验，减少了数据库查询次数。

## 功能点清单

### 1. 认证授权模块 (Auth)

- **用户注册**：支持员工注册，使用手机号作为唯一标识，密码采用 SHA-256 加密存储
- **用户登录**：支持手机号和密码登录，返回 JWT 令牌
- **自动登录**：基于 JWT 令牌实现自动登录功能
- **权限验证**：JWT 令牌验证，支持 30 天有效期

### 2. 用户管理模块 (User)

- **分页查询用户**：支持分页查询所有员工信息
- **查询所有用户**：获取系统中所有用户列表
- **查询指定用户**：根据用户 ID 查询详细信息
- **根据手机号查询**：验证手机号是否已注册
- **修改用户信息**：更新用户基本信息（用户名、手机号、角色、地址、入职日期）
- **修改用户头像**：更新用户头像 URL
- **修改密码**：支持用户修改密码，验证原密码
- **删除用户**：删除用户及其关联的订单记录（事务处理）

### 3. 产品管理模块 (Product)

- **创建产品**：添加新的汽车产品，包括名称、型号、价格、简介、海报
- **分页查询产品**：支持分页查询，同时统计每个产品的销量
- **查询所有产品**：获取所有产品列表
- **查询指定产品**：获取产品详情，包括库存分布饼图数据和年度销售趋势数据
- **查询产品库存**：查询指定产品在不同仓库的库存分布
- **修改产品信息**：更新产品名称、型号、价格、简介
- **删除产品**：删除产品及其关联的订单、供应记录、库存记录（事务处理）

### 4. 仓库管理模块 (Warehouse)

- **创建仓库**：添加新的仓库，记录仓库位置
- **分页查询仓库**：支持分页查询所有仓库
- **查询所有仓库**：获取所有仓库列表
- **查询指定仓库**：根据仓库 ID 查询详细信息
- **查询仓库库存**：查询指定仓库中所有有库存的产品信息
- **修改仓库信息**：更新仓库位置信息
- **删除仓库**：删除仓库及其关联的供应记录、订单、库存记录（事务处理）

### 5. 供应商管理模块 (Supplier)

- **创建供应商**：添加新的供应商，包括姓名、手机号、公司名称
- **分页查询供应商**：支持分页查询所有供应商
- **查询所有供应商**：获取所有供应商列表
- **查询指定供应商**：根据供应商 ID 查询详细信息
- **修改供应商信息**：更新供应商姓名、手机号、公司名称
- **删除供应商**：删除供应商及其关联的供应记录（事务处理）

### 6. 订单管理模块 (Order)

- **创建订单**：创建新订单，关联产品、员工、仓库信息
- **分页查询订单**：支持分页查询，聚合显示产品、员工、仓库的详细信息
- **查询指定订单**：根据订单 ID 查询完整信息
- **修改订单**：更新订单关联的产品、员工、仓库信息
- **删除订单**：删除订单并自动恢复相应库存（库存数量 +1）

### 7. 供应记录管理模块 (Supply)

- **创建供应记录**：记录供应商向仓库供应产品的信息，包括数量、时间
- **分页查询供应记录**：支持分页查询，聚合显示供应商、产品、仓库的详细信息
- **查询指定供应记录**：根据供应记录 ID 查询完整信息
- **修改供应记录**：更新供应数量、供应商、产品、仓库信息
- **删除供应记录**：删除指定的供应记录

### 8. 数据统计与可视化模块 (Chart)

#### 8.1 总数统计 (Total)

- **总营业额统计**：统计所有订单的总营业额（SUM(Product.price)）
- **总成交量统计**：统计订单总数
- **仓库总数统计**：统计系统中仓库数量
- **员工总数统计**：统计系统中员工数量

#### 8.2 排名统计 (Ranking)

- **员工销售榜**：统计近 5 年销售额最高的前 7 名员工，提供年度销售额数据
- **汽车热销榜**：统计近 10 年销量最高的前 7 款汽车，提供年度销量趋势数据

### 9. 文件管理模块 (Qiniu)

- **获取上传令牌**：获取七牛云对象存储的上传令牌
- **文件上传**：支持图片文件上传到七牛云，返回 CDN 访问地址

## 数据库结构设计

### 数据库概述

系统使用 MySQL 数据库，通过 Prisma ORM 进行数据管理。数据库设计包含 7 个核心实体，建立了完整的关系模型。

### 实体关系图 (ERD)

```
User (员工)
  ├── 1:N ──> Order (订单)

Product (汽车产品)
  ├── 1:N ──> Order (订单)
  ├── 1:N ──> Supply (供应记录)
  └── 1:N ──> Inventory (库存)

Supplier (供应商)
  └── 1:N ──> Supply (供应记录)

Warehouse (仓库)
  ├── 1:N ──> Order (订单)
  ├── 1:N ──> Supply (供应记录)
  └── 1:N ──> Inventory (库存)

Order (订单)
  ├── N:1 ──> User (员工)
  ├── N:1 ──> Product (产品)
  └── N:1 ──> Warehouse (仓库)

Supply (供应记录)
  ├── N:1 ──> Supplier (供应商)
  ├── N:1 ──> Product (产品)
  └── N:1 ──> Warehouse (仓库)

Inventory (库存)
  ├── N:1 ──> Product (产品)
  └── N:1 ──> Warehouse (仓库)
```

### 数据表详细设计

#### 1. User (员工表)

| 字段名      | 类型       | 约束                        | 说明                    |
| ----------- | ---------- | --------------------------- | ----------------------- |
| id          | Int        | PRIMARY KEY, AUTO_INCREMENT | 员工唯一标识            |
| username    | String     | NOT NULL                    | 员工姓名                |
| password    | String     | NOT NULL                    | 密码（SHA-256 加密）    |
| phone       | String(11) | UNIQUE, NOT NULL            | 手机号（唯一标识）      |
| role        | Role       | DEFAULT USER                | 角色（USER/ADMIN/ROOT） |
| address     | String     | DEFAULT '...'               | 地址                    |
| avatar      | String     | DEFAULT '...'               | 头像 URL                |
| joined_date | DateTime   | DEFAULT now()               | 入职日期                |

**关联关系：**

- 一对多：一个员工可以创建多个订单 (Order)

#### 2. Product (汽车产品表)

| 字段名    | 类型   | 约束                        | 说明         |
| --------- | ------ | --------------------------- | ------------ |
| id        | Int    | PRIMARY KEY, AUTO_INCREMENT | 产品唯一标识 |
| name      | String | NOT NULL                    | 产品名称     |
| model     | String | NOT NULL                    | 产品型号     |
| price     | Double | NOT NULL                    | 产品价格     |
| introduce | Text   | NOT NULL                    | 产品简介     |
| poster    | String | DEFAULT ''                  | 产品海报 URL |

**关联关系：**

- 一对多：一个产品可以有多个订单 (Order)
- 一对多：一个产品可以有多个供应记录 (Supply)
- 一对多：一个产品可以在多个仓库有库存 (Inventory)

#### 3. Supplier (供应商表)

| 字段名  | 类型       | 约束                        | 说明           |
| ------- | ---------- | --------------------------- | -------------- |
| id      | Int        | PRIMARY KEY, AUTO_INCREMENT | 供应商唯一标识 |
| name    | String     | NOT NULL                    | 供应商姓名     |
| phone   | String(11) | UNIQUE, NOT NULL            | 联系电话       |
| company | String     | NOT NULL                    | 公司名称       |

**关联关系：**

- 一对多：一个供应商可以有多个供应记录 (Supply)

#### 4. Warehouse (仓库表)

| 字段名   | 类型   | 约束                        | 说明         |
| -------- | ------ | --------------------------- | ------------ |
| id       | Int    | PRIMARY KEY, AUTO_INCREMENT | 仓库唯一标识 |
| location | String | NOT NULL                    | 仓库位置     |

**关联关系：**

- 一对多：一个仓库可以有多个订单 (Order)
- 一对多：一个仓库可以有多个供应记录 (Supply)
- 一对多：一个仓库可以有多个库存记录 (Inventory)

#### 5. Order (订单表)

| 字段名      | 类型     | 约束                        | 说明         |
| ----------- | -------- | --------------------------- | ------------ |
| id          | Int      | PRIMARY KEY, AUTO_INCREMENT | 订单唯一标识 |
| productId   | Int      | FOREIGN KEY → Product.id    | 产品 ID      |
| userId      | Int      | FOREIGN KEY → User.id       | 员工 ID      |
| warehouseId | Int      | FOREIGN KEY → Warehouse.id  | 仓库 ID      |
| createtime  | DateTime | DEFAULT now()               | 订单创建时间 |

**关联关系：**

- 多对一：多个订单属于一个产品 (Product)
- 多对一：多个订单属于一个员工 (User)
- 多对一：多个订单属于一个仓库 (Warehouse)

**业务逻辑：**

- 创建订单时，系统应自动减少相应库存
- 删除订单时，系统应自动恢复相应库存

#### 6. Supply (供应记录表)

| 字段名      | 类型     | 约束                        | 说明             |
| ----------- | -------- | --------------------------- | ---------------- |
| id          | Int      | PRIMARY KEY, AUTO_INCREMENT | 供应记录唯一标识 |
| quantity    | Int      | NOT NULL                    | 供应数量         |
| supplierId  | Int      | FOREIGN KEY → Supplier.id   | 供应商 ID        |
| productId   | Int      | FOREIGN KEY → Product.id    | 产品 ID          |
| warehouseId | Int      | FOREIGN KEY → Warehouse.id  | 仓库 ID          |
| createtime  | DateTime | DEFAULT now()               | 供应时间         |

**关联关系：**

- 多对一：多个供应记录属于一个供应商 (Supplier)
- 多对一：多个供应记录属于一个产品 (Product)
- 多对一：多个供应记录属于一个仓库 (Warehouse)

#### 7. Inventory (库存表)

| 字段名      | 类型        | 约束                        | 说明                   |
| ----------- | ----------- | --------------------------- | ---------------------- |
| id          | Int         | PRIMARY KEY, AUTO_INCREMENT | 库存记录唯一标识       |
| productId   | Int         | FOREIGN KEY → Product.id    | 产品 ID                |
| warehouseId | Int         | FOREIGN KEY → Warehouse.id  | 仓库 ID                |
| quantity    | UnsignedInt | NOT NULL                    | 库存数量（无符号整数） |

**关联关系：**

- 多对一：多个库存记录属于一个产品 (Product)
- 多对一：多个库存记录属于一个仓库 (Warehouse)

**业务逻辑：**

- 库存数量不能为负数（使用 UnsignedInt 类型）
- 每个产品在每个仓库只能有一条库存记录（通过业务逻辑保证）

### 枚举类型

#### Role (员工角色枚举)

```prisma
enum Role {
  USER    // 普通员工
  ADMIN   // 管理员
  ROOT    // 超级管理员
}
```

### 数据库设计特点

1. **数据完整性**：
   - 使用外键约束保证数据关联的完整性
   - 使用唯一约束保证手机号等关键字段的唯一性
   - 使用事务处理保证级联删除的数据一致性

2. **性能优化**：
   - 为常用查询字段建立索引（如 phone 字段）
   - 使用无符号整数类型优化存储空间
   - 合理设计表结构，避免数据冗余

3. **扩展性**：
   - 使用枚举类型便于后续角色扩展
   - 预留扩展字段（如 address、avatar）
   - 时间字段使用 DateTime 类型支持精确时间记录

4. **业务逻辑**：
   - 订单与库存联动，保证库存数据准确性
   - 级联删除保证数据一致性
   - 支持多仓库、多供应商的复杂业务场景

## 如何开始使用

1. 源代码（通过 zip 解压或 git 拉取）

```shell
    git clone https://github.com/Tako0825/car-sales.git
```

2. 配置 .env.example 示例文件为 .env 文件（补充数据库、七牛云等配置信息）

3. 安装 pnpm

```shell
    npm install pnpm -g
```

4. 安装依赖（根目录和 vue 目录下分别执行）

```shell
    pnpm install
```

5. 数据库迁徙

```shell
    npx prisma generate
```

```shell
    npx prisma migrate dev
```

6. 运行 nest 后台（根目录下执行）

```shell
    pnpm dev
```

7. 运行 vue 前台（vue 目录下执行）

```shell
    pnpm run serve
```

8. 访问项目（http://localhost:8080）
